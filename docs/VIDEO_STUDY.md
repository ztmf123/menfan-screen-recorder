# DogSC 视频分析与 Menfan 功能规格

分析日期：2026-10-26。输入是用户提供的本地录屏 `Desktop 2026.10.26 - 13.31.33.01.mp4`。
此文档记录视频展示的交互与后续验收目标，不代表这些功能已在 Menfan 中实现。
2026-10-27 的实现与验证结果分别见 [FEATURE_PARITY.md](FEATURE_PARITY.md) 和 [VALIDATION.md](VALIDATION.md)。

## 分析范围与证据

- 文件时长 322.197 秒，2560 × 1440，60 FPS，含音轨；字幕直接烧录在画面中，没有独立字幕轨。
- 覆盖全片的 8 秒采样总览；对 00:46–04:30 的主要功能演示增加 2 秒间隔采样。
- 全片以每 0.5 秒一帧提取字幕区域，生成 644 张字幕图并使用本机中文 OCR；结合画面复核。
- 对暂停、备忘录、完成卡片、样机、光标、3D、摄像头、预设、预览质量和导出等操作提取原分辨率关键帧。
- 这是分段抽帧与关键操作复核，**没有逐一人工检查约 19,000 个视频帧**。
- 以下所有时间指本地录屏时间，不是画面中 YouTube 播放器时间。片中调整过播放速度，不能统一乘二换算。
- OCR 会混入视频内的界面文字，有错别字；原始 OCR 只作定位，不作为逐字字幕或精确规格。
- 作者头像有时位于正在演示的软件之外。仅把软件画布内的摄像头图层视为被演示的产品功能。
- 设备列表入口、选项或作者讲解不等于所有设备已现场测试；例如 iPhone/iPad 主要展示选择入口和讲解。

本地辅助证据位于被 Git 忽略的 `artifacts/video-study/`：
`overview-sheet-*` 为全片总览，`dense-sheet-*` 为功能演示总览，
`keyframes/` 为高分辨率关键帧，`subtitles.json` 与 `transcript-ocr.txt` 为机器识别记录。
原视频和抽帧素材保留在本地，不加入 GitHub 发布内容。

## 产品的完整使用流程

```text
启动 → 小型来源选择工具栏
     → 选择显示器 / 窗口 / 区域 / 外接设备
     → 选择摄像头、麦克风、系统声音、保存位置
     → 开始录制
     → 更精简的录制中工具条：计时、暂停、备忘录、标记、停止、更多
     → 停止 → 录制完成卡片
                 ├─ 保存项目：继续停留在轻量录制流程
                 └─ 进入编辑：打开大编辑器
                        → 样式与多轨时间线 → 导出成片或仅音频
```

对当前版本的修正：Menfan 现在停止后直接进入编辑器，应改为先显示完成卡片。
录制前工具栏和录制中工具条也应是两种不同布局，不能一直保留来源选择等设置。
奶油配色与英文品牌名是用户指定需求，应在复现上述行为时保留。

当前 Menfan 播放器仍主要预览原片；样式、独立音轨、镜头与图层在导出阶段合成。
因此“能导出相似效果”还不能视为“具备视频里的编辑体验”。

## Windows 实现所需的数据与渲染模型

以下是依据视频功能提出的实现方案，不是对原项目内部实现的直接断言：

1. **采集会话**：屏幕、摄像头、系统声音、麦克风单独保存；同一单调时钟；光标、点击、标记与暂停区间独立记录。
2. **源时间与成片时间映射**：裁剪、删除、重排、变速统一通过映射层驱动所有轨道。
3. **场景与定时效果分层**：背景/屏幕样式/摄像头基础布局是全片配置；缩放、3D、摄影机运动、遮罩和贴图是独立时间片段。
4. **坐标分层**：屏幕源坐标 → 裁切 → 屏幕内容与遮罩 → 屏幕变换/样机 → 场景画布；摄像头与画布贴图使用自己的变换链。
5. **共享渲染规则**：预览与导出使用同一时间求值、插值、坐标和图层顺序；可采用不同分辨率，但不能采用不同效果定义。
6. **独立光标**：采集无光标屏幕，记录形状与事件；编辑时绘制。否则无法无损替换已烧入视频的系统光标。
7. **素材与配置持久化**：工程包含时间线和素材引用，场景预设只保存可复用设置；保存必须可恢复且不覆盖原素材。

具体 Windows Graphics Capture、D3D11、编码与音频接口应在开始实现时按官方文档和本机兼容测试核实。
